## 实现与参考的边界

## 本轮针对性核对结论（2026-10-30 收尾轮）

对 `dm/host/fpslock_fc27.h` 与 `dm/host/hle_fpslock.c` 的 FC 27 分支逐项对照上述 YAML 修订，结果：

| 上游内容 | 本地对应 | 性质 |
|---|---|---|
| Title ID `0100C49025D3E000`、BID `9636BCD68E2EF2C8…` | `fc27_matches` 的字符串比较 | 游戏身份事实 |
| `evaluate_write` `[MAIN, 0xDA1EE38, 8]` double `FPS_TARGET` | `fc27_tick` 写 `obj + 8` | 地址/偏移事实 |
| `evaluate_write` `[MAIN, 0xDE81DA0, 0x14C8, 0xC]` 两个 float | 本地写 `+0xC`、`+0x10` | 指针链/字段偏移事实 |
| `MASTER_WRITE` 从 `x0+248`/`x0+324` 读 `s8`/`s9` | 本地写 RenderSettings `+0xF8`/`+0x144` | 字段偏移事实；未复制指令块 |
| `FRAMETIME_TARGET` | `1000.0f / fps` | 数学关系 |
| YAML 变量、`type:` 结构、指令数组、`hasStarted` 写 1 | 无对应物 | 本地不需要该补丁钩子，C 逻辑自行实现 |

本地实现中未发现 YAML 的键名、缩进结构、指令列表、汇编操作数排列或注释文字被复制；读写回调、指针对齐/范围检查、写保护（`svc_guest_range` + `vm_region_64`）、字段合理性判断和位掩码返回值均为本项目自有表达。四个函数的组织方式与上游配置的“声明 + 写入表 + 汇编补丁”结构不同。

**结论**：本轮未发现未经许可复制的独特代码表达，只有技术地址、数值和调节方案被参考。因此保留现有实现，不做重写或删除；FPSLocker 参考关系继续如实记录，不把参数称为独立原创，也不把 Warehouse 描述为 GPL。该判断是工程层面的表达比对，不等于取得权利人的明示许可；若权利人日后提出具体主张，再按具体部分处理。

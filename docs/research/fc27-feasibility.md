The unmodified rewriter fails to decode original `main`. The existing rewriter completed on the LZ4 SDK and on the NRO, producing gates and fixups in scratch; no execution followed. ## Route and acceptance gates

1. **A — modules and SDK.** Extend or wrap the shared NSO readers with a license-compatible ZBIC decoder, strict length/hash checks and negative tests. Design range-safe rewriting in `dm/tools/patch_nso.py` / `nso_asm.py`; verify every generated branch, segment and fixup for both builds. Register a new profile and investigate NRR/NRO binding and the two TLS symbols. Map SDK 22 SVCs and service calls to `dm/host` with explicit ABI checks. **Pass:** both real main builds, SDK and required NRO decode and rewrite with verified hashes and no out-of-range branch; loader resolves required symbols and reports unsupported operations rather than claiming success.
2. **B — graphics.** Trace render NRO's NVN loading and object sizes against `dm/gfx/nvn`; identify `.toc`/`.cas` index, compression and shader payloads, and add a bounded scanner if needed. Capture, compile and audit representative target shader programs and cache identity. **Pass:** a real frame from the target host with recorded version, logs and image plus all used shader pipelines accounted for; a static scan alone is not a pass.
3. **C — runtime.** Bring up boot, menu and a basic scene; investigate files and update overlay, audio/codec/video, account/device saves, network/offline paths and DLC against `dm/host` services. **Pass:** documented menu and scene, repeatable save/relaunch, observed audio/video and explicitly recorded network/DLC behavior with no unexplained fatal errors.
4. **D — packaging and regression.** Add profile/version selection and external resources via registry, `scripts/` and the historical packaging prototype (not shipped here); audit module IDs, required shaders, content ownership, artifacts and exclusion of keys/game data. **Pass:** independently built and audited Mac app and unsigned IPA, real runtime evidence per platform, and targeted shared-code regressions. First resolve ZBIC integration and large-text rewrite, identify the render NRO's binding sequence, and locate real shader payloads before judging overall feasibility. No probability or schedule is justified.

### Large-module checks and limits

The reference chooses a conservative total patch-size upper bound, reserves an aligned PRE below module base, and prefers AFTER when the whole site's source/return span can reach it even when full. Otherwise it places the unit in PRE if the whole span can reach that region; otherwise it fails. It routes window groups and jump tables as units. The independent `structck.py` and `equiv.py` understand the negative island offset and exclude zero padding; `tests/test_patch_island.py` exercises routing, corrupted islands and semantic checks. nxnative's general code recognises build-gated patches, data areas and large functions in pieces (`dm/tools/nso_code.py`, `dm/tools/patch_nso.py`, `dm/tools/nso_asm.py`), but its single FAR placement and current layout contract differ.

Executed a 186 MiB one-function synthetic fixture (`tests/synth_giant.py --mib 186 --every 4096 --keep --structck`), containing x18 sites, an exclusive window, SVC and a jump table. It was generated, but the reference rewrite was **manually interrupted** after prolonged processing when process sampling showed a 7.9 GiB peak physical footprint. No GIANT verdict, branch coverage or structural check was produced. An independent attempt on FC27's normalized update `main`, with `DM_RULESET=native` and `DM_PRIVATE_GATES=0`, was also interrupted during the initial instruction scan under memory pressure; no rewrite artifact or proof resulted. The earlier statement that the single-region nxnative layout needs redesign remains an inference from its range assumptions, not a measured failure of the FC26 two-island layout.

The first `test_patch_island.py` run: 14 tests, 8 skipped, remainder passed. A second run with Unicorn and Xcode's `llvm-objdump`: 19 tests, 5 failed and 2 skipped; the positive structural check failed because the adjacent `llvm-objcopy` executable was absent, and four corruption checks lacked the expected final checker output. Some other synthetic and Unicorn tests passed. `logs/fc26-island-tests-full.log` preserves exact results. Do not treat these as full structural or equivalence verification. No completed target rewrite exists, so all target branches, jump tables, RELA/RELR fixups, island boundaries and runtime mapping remain **unverified**.

## Stage 2: NSO decode and large-text preflight

Status: **neither blocker is solved**. This section distinguishes a fail-closed guard from a working decoder or dual-area rewriter.

### ZBIC and provenance

The repository has no ZBIC decoder. NSO flags 0–2 select compression per section, 3–5 select hashes, bit 6 is execute-only memory and bit 7 selects ZBIC instead of LZ4 for compressed sections. The ZBIC frame uses a different magic and a modified FSE normalized-count representation based on binary interpolative coding; changing only the magic does not decode that entropy table. The [nxdumptool change](https://github.com/DarkMatterCore/nxdumptool/commit/441e5c0904f29427987433be4eb057a2843d222a) explicitly identifies the Atmosphère ZBIC variant it uses; [Atmosphère](https://github.com/Atmosphere-NX/Atmosphere) is GPL-2.0 except its stated Nintendo-specific exception, and the independently installed [zbic Python package](https://github.com/kinnay/zbic) is GPL-2.0. Ordinary [Zstandard](https://github.com/facebook/zstd) is BSD/GPL dual licensed but does not by itself implement this variant. No license-compatible implementation with established provenance was identified in this investigation. A permissive implementation or explicit rights clearance plus review is required before integration; this is a provenance assessment, not a legal opinion.

Earlier external analysis independently decompressed **both** base and update using the GPL tool in scratch and checked each original NSO segment's declared length and SHA-256. Base text/ro/data digests are `68d672371b16d23207dd210957ae41cb8b97aa5723e7e4d8505e3226a95bfcc7`, `ab55008a7dbb969173c086e0fee8fd7aa469bf24cbd21a9ea9d06010121829bc`, `c101cbd70abeb73d27f7edf7d32411a08dd759a09a9de2752849c00f1706a40e`; update digests are `ba3320df5d27d6105ffaeebf2a9b716bde91d4798ded16f1da0a3c3447bf0495`, `06f5effbf84f50a177d63fb9dcfced493bb6a6d8b302555b789f5c7cbb9f2bee`, `16357bcf04c711492af0867619756952534fc2febb964e43661254e2e2d3f00d`. Build IDs are those in the module table above. These are experiments using one external implementation, not a legally cleared or independently implemented decoder in this repository. Bounds and malformed-frame behavior of that external implementation have not been established here.

`dm/tools/patch_nso.py` now rejects a ZBIC-flagged compressed NSO explicitly before passing it to LZ4. It does not decode ZBIC; other readers still require work. `logs/stage2-raw-base.log` and `logs/stage2-raw-update.log` record the expected rejection of both original inputs. Tests for ZBIC frame corruption, truncation, incorrect lengths, unknown flags and hash mismatch are still required when a real decoder is integrated.

### Layout design and preflight

AArch64 `B` encodes a signed word displacement in `[-0x8000000, 0x7fffffc]` bytes. `dm/tools/nso_asm.py` now raises on an unaligned or out-of-range branch even with Python `-O`; this is not a proof of generated branch coverage. The current FAR design has only one patch area before the module. For text at least `0x7ff0000` bytes, `patch_nso.py` now conservatively rejects the layout before allocating the image, even if `DM_PATCH_FRONT` is set. This does not prove that every such module has an unreachable site; it prevents claiming general coverage with the existing single-area contract. Both normalized target builds were independently rejected in this preflight, not rewritten. `logs/stage2-base.log` and `logs/stage2-update.log` preserve the result.

A possible future two-area design needs: a reserved PRE and AFTER with explicit addresses and used/capacity bounds; placement of each entire exclusive window, jump-table unit and all exits in a region reachable both ways; explicit failure for impossible groups or capacity; signed gate and fixup offsets without overlap; checked branch and ADRP encodings; and relocation targets/data bounds preserved across rewriting. The macOS loader needs one reservation with validated image, island permissions and module boundaries. The iOS embedded sections and generation path require a separately verified mapping contract, not an assumption that the current one-region FAR path accepts a second area. `DM_CHUNK`/lazy disassembly addresses memory pressure but does not itself prove instructions, control flow or semantics. No such production layout, loader modification or target-specific cut was added in this stage.
